# 기억 도입 워크플로우 (현 스택 근사판)

> 목표: **그래프·Redis·GraphDB 없이**, 지금 neutda-ai 부품만으로 "이 사용자가 전에 한 말을 기억해서 답한다"를 만든다.
> 방식: **장기 = 개인 RAG(U_ID)**, **단기 = 서버측 세션기억(S_ID)**. 전부 인터페이스로 감싸 나중에 뒤(Redis/pgvector/그래프)만 교체.
> 상세 설계는 [단기기억과-장기기억.md](단기기억과-장기기억.md) 참조. 이 문서는 **구현 순서(작업목록)**.

---

## 재활용 맵 (이미 있는 것 → 어디에 씀)

| 기억 조각 | 기존 자산 | 파일 |
|---|---|---|
| 검색 결과 → 프롬프트 주입 | RAG 주입 seam (`formatRagContext`/`ragSystemAddon`/`body._rag`) | `src/server.js`, `src/ragContext.js` |
| 의미/키워드 검색 | `retrieve`(BM25)/`retrieveAsync`(코사인) | `src/rag.js` |
| 임베딩 생성 | `setEmbedder` ← `pool.embed` | `src/rag.js`, `src/pool.js` |
| 단기 히스토리 자르기/주입 | `selectHistoryTurns` | `src/historyContext.js` |
| 읽기측 요지 파악 | 라우터 분류 | `src/router.js`, `src/llmRouter.js` |

**정말 새로 짜는 것**: `U_ID/S_ID` 스코핑 + 세션 저장소 하나 + 개인 기억 저장소 하나 + 되쓰기 훅.

---

## Phase 0 — API에 U_ID / S_ID 수용

- [ ] `src/server.js` 채팅 엔트리(`POST /api/chat`, `POST /api/chat/stream`, `GET /api/ask`)에서 `body.U_ID`, `body.S_ID`(문자열, **옵션**) 읽기.
- [ ] 둘 다 없으면 **익명 = 기억 비활성** → 지금 동작 그대로(하위호환 보장).
- **DoD**: U_ID/S_ID를 보내도 기존 요청이 깨지지 않는다.

## Phase 1 — 단기(작업)기억: 서버측 세션 스토어 (S_ID)

- [ ] **신설** `src/sessionMemory.js` — 인터페이스 우선.
  - `get(sid) -> turns[]` / `append(sid, {role, content})` / `clear(sid)`
  - 초기 구현 = **인메모리 `Map<sid, {turns, expiresAt}>` + 슬라이딩 TTL**. (나중 Redis 교체 지점)
- [ ] `src/server.js` 채팅 흐름: `S_ID` 있으면 `sessionMemory.get(sid)`를 **기존 `HISTORY` 자리로 주입**(클라이언트 `HISTORY`보다 서버 세션 우선, 또는 병합). `buildMessages`/`selectHistoryTurns`는 **그대로 재사용**.
  - 참고: 현재 `HISTORY`는 클라이언트가 매번 넘김 → 서버가 들고 있게 바꾸는 것.
- [ ] 답변 완료 후 `sessionMemory.append(sid, 사용자턴)` + `append(sid, 어시스턴트턴)`.
- [ ] **compaction(1차)**: 최근 N턴만 유지(단순 cap). 롤링 요약은 Phase 3.
- **DoD**: 같은 `S_ID`로 2턴 진행 시, 클라이언트가 히스토리를 안 넘겨도 2턴째가 1턴 내용을 기억한다.

## Phase 2 — 장기(회상)기억: 개인 기억 저장소 (U_ID)

- [ ] **신설** `src/memoryStore.js` — `rag.js`의 BM25+코사인 패턴을 U_ID 키로 재사용.
  - `remember(uid, text, meta?)` / `recall(uid, query, k) -> hits[]`
  - 저장: `data/memory/<uid>.json` (또는 단일 인덱스 + `userId` 필드). 임베딩은 `setEmbedder`(pool.embed) 재사용.
  - 대안(최소 변경): `rag.js` 청크에 `userId` 필드 + `retrieve/retrieveAsync`에 `userId` 필터 한 줄 — 단, 문서-RAG와 섞이니 **분리(신설) 권장**.
- [ ] `src/server.js` 채팅 흐름: `U_ID` 있으면 `recall(uid, 질문, k)` → hits → **기존 RAG 주입 seam으로 컨텍스트 삽입**(문서 RAG와 별개 블록으로 공존).
- [ ] **되쓰기(비동기)**: 답변 후 `remember(uid, 이번 턴)`. **우선 원문 저장(추출 없음)** — 가장 빠른 근사.
- **DoD**: 같은 `U_ID`, **새 `S_ID`(세션 교체)** 에서 이전 세션에 말한 사실을 회상해 답한다.

## Phase 3 — 다듬기 (선택, 품질 향상)

- [ ] 되쓰기를 **"한 줄 사실 증류"** 로 (라우터/소형모델 1콜, 비동기) → 원문 대신 사실 저장.
- [ ] 세션 compaction에 **롤링 요약** 추가(예산 초과분만 증분 요약).
- [ ] `recall` **임계값 가드**(유사도 낮으면 주입 안 함) + **rerank**(유사도+최신성).
- [ ] U_ID/S_ID **개인정보 처리**: 삭제/열람 엔드포인트(개인정보보호법 대비).

---

## 이번에 의도적으로 보류 (그리고 대가)

- **그래프·엔티티 해소·모순(supersede)** → "관계로 뻗기", "이직함" 처리 불가. 얻는 건 **의미 회상**까지. (v1 충분)
- **Redis / pgvector / GraphDB** → 미도입. 인메모리 Map + JSON + 코사인으로 근사.

## 무손실 업그레이드 경로 (인터페이스만 지키면 뒤만 교체)

| 지금 | → 나중 |
|---|---|
| `sessionMemory` 인메모리 Map | Redis |
| `memoryStore` JSON + 인메모리 코사인 | Postgres + pgvector |
| 원문 턴 저장 | 증류된 사실(엔티티/트리플) |
| 개인 RAG 회상 | + GraphDB 관계 회상(연상·모순) |

**원칙**: `sessionMemory` / `memoryStore`를 **인터페이스로 감싸** 저장/검색 뒤단을 언제든 갈아끼울 수 있게 한다.

---

## 요약 순서

`Phase 0 (U_ID/S_ID 수용)` → `Phase 1 (서버 세션기억)` → `Phase 2 (개인 RAG 회상 + 되쓰기)` → `Phase 3 (증류·요약·가드·개인정보)`

Phase 2까지 완료 = **"세션 넘어 사용자를 기억"** 하는 MVP. Redis·GraphDB 없이 며칠 규모.

## 부록 — 최소 리소스 프로토타입 (신규 파일 0, 반나절)

> 목적: **개념 검증**. "기억하는 것처럼" 보이게, 가장 적은 코드로.
> 핵심: **기존 RAG 저장소를 기억 창고로 그대로 전용한다.** 매 턴을 `rag.addDocument`로 넣고, RAG가 켜져 있으면 `retrieveAsync`가 과거 턴을 알아서 회상·주입한다. (위 Phase 계획의 "Phase -1")

### 단계
1. **요청에 RAG on** — 기존 RAG 플래그(`RAG`/`rag=true`) 재사용. 새 코드 없음.
2. **되쓰기 훅 1줄** — 답변 완료 지점(`appendHistory(...)` 부르는 자리 옆)에서:
   ```js
   // fire-and-forget (응답 블로킹 X)
   rag.addDocument("mem", `Q: ${질문}\nA: ${답변}`).catch(() => {});
   ```
   (`server.js`는 이미 `import * as rag from "./rag.js"` 되어 있음)
3. **회상** — 다음 질문(RAG on)이 오면 `retrieveAsync`가 과거 턴을 뽑아 **기존 RAG 주입 seam**으로 넣는다 → 모델이 "기억".

### 재활용 (신규 파일 0)
`rag.addDocument` · `retrieveAsync` · `prepareChatRag` 주입 seam · 기존 "답변 완료" 훅.

### 한계 (정직하게)
- **전역 단일 기억** — 사용자/세션 구분 없음 → 데모·단일 사용자용.
- **원문 저장**(증류 없음), **문서-RAG와 섞임** — 이름 접두(`mem:`)로 구분/삭제는 가능.
- 매 턴 `addDocument` = `index.json` 전체 재기록(O(N)) → **소규모 데모만**.
- 단기/장기 구분 없음 — 그냥 "누적 회상".

### 검증 (반나절 안에 확인)
1. "나 파이썬 좋아해" 대화 → 저장됨.
2. 새 질문 "내가 뭐 좋아한다고 했지?" (RAG on) → **"파이썬" 회상**.

### 프로토 → 정식 승격
이 프로토에 **U_ID 스코프(`memoryStore` = Phase 2)** + **S_ID 세션(`sessionMemory` = Phase 1)** 만 얹으면 위 Phase 계획으로 자연 승격된다. 즉 버릴 코드가 아니라 **씨앗**.
